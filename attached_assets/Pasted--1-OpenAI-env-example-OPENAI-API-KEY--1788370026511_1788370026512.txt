🔴 Самые важные ошибки
1. OpenAI сейчас вообще не подключён

В .env.example есть:

OPENAI_API_KEY=

Но в серверном коде нет использования OPENAI_API_KEY и нет вызова OpenAI API.

То есть:

Market AI → работает только на заранее написанном demo-алгоритме
StudyAI → demo-текст
Assistant → demo-текст
SafeHelp → demo-ответ

Это главная причина, почему приложение пока не является настоящим AI LifeHub.

Что исправить: сделать серверный AI-слой:

Frontend
   ↓
/api/ai/...
   ↓
API server
   ↓
OpenAI API
   ↓
структурированный ответ
   ↓
Frontend

И ключ оставить только на сервере.

2. Фото товара фактически НЕ анализируется

В Market:

const [imageName, setImageName] = useState<string | null>(null);

После выбора изображения сохраняется только:

e.target.files?.[0]?.name

То есть сервер получает примерно:

{
  "title": "MacBook Air M2",
  "price": 500,
  "imageName": "photo.jpg"
}

Самой фотографии там нет.

Поэтому надпись:

«A photo makes the read more specific»

сейчас фактически неправда.

Что исправить: передавать изображение на сервер или использовать подходящий image-input для AI.

3. Оценка цены сейчас ненастоящая

В ai.ts:

const estimatedPriceMin = Math.max(10, Math.round(price * 0.85));
const estimatedPriceMax = Math.round(price * 1.18);

То есть если продавец просит $500, приложение примерно вычислит:

$425–590

Независимо от того, что это за товар.

Это не анализ рынка.

Нужно: либо подключать реальные источники данных/поиск, либо честно называть это примерной demo-оценкой, пока реальный поиск не сделан.

4. В Favorites есть логическая ошибка

Сохраняется:

const key = `${result.brand}-${result.model}`;

А потом поиск сохранённых товаров делается через:

favorite.includes(item.result.brand)

Это работает случайно, но сама система идентификации плохая.

Например, если несколько товаров имеют одинаковый brand, возможны неправильные совпадения.

Лучше:

favorites = [marketItem.id]

и потом:

markets.filter(item => favorites.includes(item.id))
5. Language в Settings ничего не меняет

Можно выбрать:

English
Українська
Polski

Но интерфейс не переводится.

То есть настройка сейчас просто сохраняется в localStorage.

Нужно добавить i18n, например:

English
Українська
Polski

и реальные переводы всех страниц.

🟠 Ещё важные проблемы
6. Дата на Dashboard захардкожена

Сейчас:

Tuesday, 14 May · your cockpit is ready

Она не обновляется.

Через некоторое время пользователь будет видеть неправильную дату.

Исправить на динамическую дату.

7. Dashboard использует API, но при ошибке скрывает проблему

Например:

const summary = summaryQuery.data ?? {
  topicsLearned: storage.studies().length,
  ...
};

Если API-сервер упал, пользователь просто увидит demo/local значения.

Это удобно для demo, но при разработке сложно понять, что backend сломан.

Нужен нормальный статус:

● AI service connected
● Demo mode
⚠ API unavailable
8. Activity API тоже полностью demo

Сервер возвращает:

[
  { id: "a1", ... },
  { id: "a2", ... },
  { id: "a3", ... }
]

То есть Dashboard может показывать:

Повторение дробей
Проверка MacBook Air

даже если пользователь никогда этого не делал.

Нужно либо убрать эти fake-записи, либо явно пометить их как пример.

9. SafeHelp слишком примитивно определяет опасные ситуации

Сейчас используется regex:

/прямо сейчас|угрожает|опасност|насили|пожар|травм|оружи|не могу уйти/i

Проблемы:

русский язык частично поддерживается;
украинский поддерживается плохо;
английский практически не учитывается;
возможны ложные срабатывания;
возможны пропуски опасных ситуаций.

Для SafeHelp это особенно важно.

10. SafeHelp показывает слишком общий emergency contact

Сейчас:

Взрослый рядом и соответствующая экстренная служба

Лучше сделать локальную систему:

🇺🇦 Ukraine

112 — emergency
101 — fire/rescue
102 — police
103 — ambulance
104 — gas

Но номера и инструкции лучше хранить как проверенные локальные данные, а не генерировать их AI.

14. StudyAI «Check my thinking» не проверяет ответ

  "question": "...",
